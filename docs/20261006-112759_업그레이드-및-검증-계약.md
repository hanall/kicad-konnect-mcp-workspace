## 공개 계약 변화와 migration

1. 심볼 검색은 단일 `.kicad_sym`와 KiCad 10 `.kicad_symdir`를 모두 처리합니다. 프로젝트 nickname 우선순위, dedup, limit=0, unreadable 오류가 회귀 시험으로 고정됩니다. broad 검색에는 등록 library table이 필요합니다.
2. `move_connected`는 요청을 무시하지 않습니다. 기존 net 동등성을 실제 CLI로 증명하고 pin geometry/UUID가 불명확하거나 안전한 두 직각 경로가 없으면 원본을 보존한 채 거부합니다.
3. whole-footprint live IPC는 원문 snapshot에 보존 불가 토큰이 있으면 쓰기 전에 거부합니다. 닫힌 PCB 갱신은 `allow_closed_board_file:true`가 필요하고 `dry_run:true`가 반환한 `plan_revision`을 `expected_plan_revision`으로 전달해야 합니다. 허용되지 않은 group·variant·소유권불명 객체는 무리하게 변환하지 않습니다.
4. schematic-to-PCB 동기화는 필드 삭제/빈 값/PCB 전용 필드·UUID·net·geometry를 구분하며 stale plan, target drift, 외부 writer를 보호합니다. 오류나 rollback을 무조건 성공으로 보고하지 않습니다.
5. config의 비-null JSON 값, LCSC 최신 `pdfUrl` 및 오류 분류, SemVer build metadata, IPC-D356 CLI 명령과 nm 반올림을 교정했습니다.
6. viewer는 별도 lockfile을 유지한 localhost browser 구조입니다. loopback + 난수 URL + same-origin 요청, snapshot render, page/state/SVG/img.onload 확인이 ready 조건입니다. 더 이상 Tauri/GTK/WebKit 설치를 요구하지 않습니다.
7. `KONNECT_RUNTIME_HOME`은 프로젝트 `.runtime-home` 또는 `.artifacts` 하위 전용 canonical 경로만 허용합니다. 새 환경변수를 사용하지 않으면 기존 기본값이 유지됩니다.

8. `set_active_layer`는 KiCad typed Get/Set/Get의 동일 DocumentSpecifier와 응답 재조회를 확인합니다. Set 전송 뒤 응답·재조회 실패는 적용 안 됨으로 단정하지 않고 `ipc_outcome_unknown`, `retry_safe:false`로 구분합니다. 보드 파일 쓰기를 동반하지 않습니다.
9. `resolve_cross_probe_target`의 기본값은 정확한 양쪽 live identity를 요구합니다. KiCad 10.0.6 manager가 반환하는 project 없는 schematic basename을 추정으로 승격하지 않습니다. 명시 `allow_saved_schematic_context:true`는 root-only 저장 schematic과 검증된 live PCB의 읽기 전용 mapping이며, schematic live identity가 증명되지 않았음을 응답에 명시합니다. sch/pcb bytes SHA와 재해석 결과가 호출 전후 달라지면 `stale_target`으로 거부하며 selection/activate/reveal로 이 완화를 전달하지 않습니다.

상세 공개 응답·거부·rollback 계약은 `upstream/konnect/docs/API_MIGRATIONS.md`에 있습니다.

## 재현 gate

```bash
make verify
make check-local
make runtime-verify
```

`make check-local`은 upstream 조회, root provenance, Rust fmt/unit/doc/all-target Clippy, 별도 viewer 시험, root Python 시험, release build, MCP smoke를 수행합니다. 실제 GUI·네트워크·제조와 audit는 아래 별도 gate이므로 명령 성공 하나로 모두 통과했다고 표현하지 않습니다.

```bash
cargo audit --file upstream/konnect/Cargo.lock
cargo audit --file upstream/konnect/crates/schematic-viewer/Cargo.lock
python3 scripts/mcp-catalogue-coverage.py capture \
  --output-dir .artifacts/final-catalogue --execute-refusal-probes
python3 scripts/mcp-headless-functional.py \
  --output-dir .artifacts/final-headless --timeout 180
python3 scripts/mcp-pcb-functional.py \
  --output .artifacts/final-pcb --lane kicad-mcp-pcb-tests --fresh
python3 scripts/mcp-service-functional.py run \
  --inventory .artifacts/final-catalogue/inventory.json \
  --output-dir .artifacts/final-services
```

PCB runner 기본 inventory 경로가 현재 final과 다르면 `--inventory`로 위 파일을 명시합니다. fixture 생성·GUI/IPC는 전용 ACUW lane/소켓/HOME에 한정합니다. 서비스의 대용량 공개 DB 다운로드·실제 네트워크·Freerouting은 별도 ledger 조건을 확인합니다. `--allow-stale-binary`로 최종 source gate를 우회하지 않습니다.

```text
freeze -> tests -> fork commit -> lock -> build -> SHA-bound runners
       -> strict live acceptance -> root commit -> hanall push -> SHA readback
```

## Linux PCM 검증 도구

원본 `packaging/validate-pcm.py`에 필요한 `jsonschema`는 application dependency가 아닌 별도 검증 도구입니다. `config/pcm-schema-validator.lock.txt`에 6개 package와 126개 wheel hash를 고정했습니다. 최초 설치 때 모든 전이 package의 공식 PyPI metadata·공개나이·yanked 여부와 홈 guard를 확인했고, 최소 공개 age 95일, installed/lock 취약점 0, `.pth` 감사 통과를 기록했습니다. PyPI provenance가 없는 자료를 Trusted Publisher 서명 검증으로 표현하지 않습니다.

기존 Python 3.12와 uv가 있는 호스트에서만 아래를 실행합니다. 없어도 시스템 도구를 조용히 설치하지 않습니다.

```bash
UV_PYTHON_DOWNLOADS=never uv venv --python python3.12 \
  .artifacts/pcm-schema-validator/.venv
uv pip sync --require-hashes --no-build \
  --python .artifacts/pcm-schema-validator/.venv/bin/python \
  config/pcm-schema-validator.lock.txt
.artifacts/pcm-schema-validator/.venv/bin/python \
  upstream/konnect/packaging/validate-pcm.py \
  --metadata upstream/konnect/packaging/metadata.json
```

새 설치 시에는 공통 guard와 감사 절차를 다시 적용합니다. 현재 Linux zip과 metadata는 공식 validator 통과, Windows PE를 Linux로 위장한 mutation은 실패를 확인했습니다. Nix 및 Windows/macOS 실제 build·package 검증은 해당 환경이 없어 미실시이며 Linux의 성공으로 대체하지 않습니다.

## 증거와 판정

- 원 rc, request/response, 바이너리 SHA, 빌드 입력 digest, PID/exe, GUI 소켓·board identity를 남깁니다.
- RED는 제품 동작 실패와 준비/의존성 실패를 분리합니다. mutation은 보호 단언을 실제로 제거했을 때 시험이 실패하는지 확인하고 소스 복원 뒤 GREEN2를 요구합니다.
- functional fixture는 고의 DRC 위반을 포함할 수 있습니다. 이 fixture의 기능 통과를 제조 승인으로 승격하지 않습니다.
- 데모의 ERC/DRC 전체 범주 0, 4 footprint/8 pad/9 trace/3 net/0 unconnected와 실제 재오픈·3D 화면은 별도 검증합니다.
- 모든 공개 도구 호출의 정상 경로를 실증하더라도 모든 OS·모든 인자·동시 writer·미래 버전·공급자 자료 진위를 절대 보장하지 않습니다.

## rollback

- 공유 checkout에서 `reset --hard`, broad stash/add 또는 타 세션 변경 취소를 하지 않습니다.
- 회로는 `.artifacts/20261006-upgrade/backups`와 MCP 전후 snapshot을 보존합니다. GUI를 닫고 exact identity를 확인한 뒤 승인된 복원만 수행합니다.
- source rollback은 두 저장소에서 개선 commit을 별도 revert하고 root gitlink/lock을 같은 검증된 commit으로 되돌립니다. 구 바이너리를 복사하는 것만으로 source/runtime 정합성이 복구된 것으로 보지 않습니다.
- 이전 KiCad `/opt/kicad/10.0.5`를 보존했습니다. 전환 시 8개 wrapper·desktop·manifest를 함께 복원·검증해야 합니다. 단일 symlink만 바꾸지 않습니다.
- Freerouting은 프로젝트 artifact 아래 선택 런타임을 격리하므로 시스템 Java와 alternatives를 되돌릴 필요가 없습니다. 정리 전 lock/manifest/SHA를 대조합니다.
- root와 fork의 GitHub Actions는 계속 비활성입니다. 공식 upstream remote/tag로 push하지 않습니다.
