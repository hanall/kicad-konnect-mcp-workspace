# 개발 로드맵

## 0단계: 재현 가능한 기반

- [x] KiCad 10.0.5와 Konnect v0.2.2 공식 source pin
- [x] root meta-repository와 submodule 구성
- [x] 프로젝트 격리 MCP launcher
- [x] source provenance와 공급망 검사
- [ ] KiCad 10 Linux runtime 확보와 `kicad-cli version` 검증

## 1단계: 실제 회로 acceptance fixture

작은 전원 LED 보드를 기준 fixture로 만듭니다.

1. project 생성
2. symbol/footprint 배치
3. net 연결
4. ERC
5. PCB update, 배치, routing
6. DRC
7. Gerber, drill, BOM, position 생성
8. 출력 manifest와 SHA-256 기록

성공 기준은 tool call 성공이 아니라 KiCad가 다시 연 파일, ERC/DRC report, 제조 산출물의 교차 일치입니다.

## 2단계: MCP 신뢰성 강화

- tool 입력 path를 `projects/` 아래로 제한하는 정책 계층
- destructive edit 전 snapshot/rollback
- tool call과 Git commit의 상관관계 ID
- timeout, subprocess cancellation, stale IPC socket 복구
- 전체 193개 도구의 schema snapshot 회귀 테스트

## 3단계: 제조 품질 gate

- 제조사별 최소 trace/clearance/via 규칙 profile
- BOM lifecycle와 대체 부품 정책
- polarity, pin-1, connector orientation review
- Gerber stack, drill pair, board outline, solder mask 검증
- 독립 viewer 또는 CAM 검증 결과 첨부

## 4단계: 사업화 경계

- AGPL 공개 배포 모델과 Konnect commercial license 모델 비교
- 고객 회로 데이터의 로컬 처리와 보존 기간
- 모델 제공자별 데이터 반출 정책
- 설계 승인과 발주 승인 권한 분리
