### 지속 업데이트 계약

- KiCad는 공식 GitLab 원본에서 `.99.0` 개발 태그를 제외한 최신 안정 release를 추적한다.
- `make check-updates`로 drift를 확인하고 `make update-kicad`로 tag, commit, gitlink, 잠금 파일을 함께 갱신한다.
- KiCad 소스에는 프로젝트 고유 변경을 넣지 않는다.
- Konnect 개선은 `hanall/Konnect`의 `hanol-dev/*` 브랜치에서 수행하고 공식 `mixelpixx/Konnect`는 upstream 동기화 기준으로 유지한다.
- Qucs-S와 LTspice는 자동 갱신하지 않는다. 새 버전은 SHA256·버전·게시일을 `config/qucs-s.lock.json`·`config/ltspice.lock.json`과 설치 스크립트 상단 상수에 동시에 반영하고 7일 age gate를 지킨 뒤 `make install-qucs-s`·`make install-ltspice`로 설치한다. LTspice `latest` URL의 파일이 잠금 SHA256과 다르면 설치는 중단된다.
- 시스템 ngspice와 Wine은 Debian 패키지라 이 호스트의 unattended-upgrades로 바뀔 수 있다. `make sim-runtime-verify`가 패키지 버전 불일치로 실패하면 `make sim-verify`와 LTspice 재검증을 다시 돌린 뒤 잠금 파일·설치 스크립트 상수·계약 문서를 함께 갱신한다.
- `make check-updates`는 KiCad·Konnect(`upstreams.lock.json`)만 확인하며 시뮬레이터 drift는 확인하지 않는다.

## 1단계: 실제 회로 acceptance fixture

작은 전원 LED 보드를 기준 fixture로 만듭니다.

1. project 생성
2. symbol/footprint 배치
3. net 연결
4. ERC
5. PCB update, 배치, routing
6. DRC
7. Gerber, drill, BOM, position 생성
8. 출력 manifest와 SHA-256 기록

성공 기준은 tool call 성공이 아니라 KiCad가 다시 연 파일, ERC/DRC report, 제조 산출물의 교차 일치입니다.

## 2단계: MCP 신뢰성 강화

- tool 입력 path를 `projects/` 아래로 제한하는 정책 계층
- destructive edit 전 snapshot/rollback
- tool call과 Git commit의 상관관계 ID
- timeout, subprocess cancellation, stale IPC socket 복구
- 현재 Linux STDIO 236개 도구의 catalogue/schema/정상·거부 ledger와 source SHA 결속

## 3단계: 제조 품질 gate

- 제조사별 최소 trace/clearance/via 규칙 profile
- BOM lifecycle와 대체 부품 정책
- polarity, pin-1, connector orientation review
- Gerber stack, drill pair, board outline, solder mask 검증
- 독립 viewer 또는 CAM 검증 결과 첨부

## 4단계: 사업화 경계

- AGPL 공개 배포 모델과 Konnect commercial license 모델 비교
- 고객 회로 데이터의 로컬 처리와 보존 기간
- 모델 제공자별 데이터 반출 정책
- 설계 승인과 발주 승인 권한 분리
- LTspice 비공개 사용권과 제조사 SPICE 모델 사용 조건의 사업용 적용 검토

## 5단계: 회로 시뮬레이션 검증

AI가 Konnect MCP로 회로도에 시뮬레이션 모델을 붙이고, SPICE 넷리스트를 내보내 여러 엔진에서 같은 판정을 재현하는 흐름을 만듭니다. 설치·버전 정본은 [시뮬레이터 구성 계약](agents/20261022-172859_circuit-simulators-linux.md), AI 작업 절차는 [`skills/kicad-simulation/`](../skills/kicad-simulation/SKILL.md)입니다.

- [x] 엔진 중립 검증 회로 5종(RC 과도응답, MOSFET 게이트 구동, OP AMP 비반전 증폭, 다이오드 반파 정류, 프리차지 돌입)의 이론값·허용 오차 사양과 `make sim-verify` 회귀
- [x] `KONNECT_SIM=1` STDIO 중계 도구 4종(엔진 목록, SPICE 넷리스트 내보내기, Sim 모델 설정, 배치 실행·측정 판정) 확정과 `make test-sim-mcp` 통과 기록
- [x] 시뮬레이션 도구 입력 경계: `directives`·입력 넷리스트의 `.control`/셸 명령 거부, 넷리스트·작업·포함 경로의 `projects/`·`.artifacts/` 제한과 거부 입력 회귀
- [x] KiCad 회로도 → SPICE 넷리스트 경로를 검증 회로 5종 전체로 확대(2026-10-22 진행 중)
- [ ] 경로 간 1% 교차 판정 자동화와 LTspice 파형 압축 조건(`.options plotwinsize=0`) 정리
- [ ] 2차 과제: 사용자 핵심 IC의 제조사 모델 검증. 모델 파일 형식(일반 SPICE, 암호화 PSpice, LTspice 전용)과 사용 조건 확인부터 시작

성공 기준은 시뮬레이션 실행 성공이 아니라 회로도 필드, 내보낸 넷리스트, 엔진 로그, 측정값과 이론값의 교차 일치입니다.

## 2026-10-06 검증 범위

5V LED 데모를 MCP로 생성했고 실제 KiCad 10.0.6에서 ERC/DRC 전체 범주 0을 확인했습니다. 상세 기능 시험과 소스·바이너리 식별자는 같은 날짜 보고서가 정본입니다. 실물 보드 발주·조립·전원 인가, 모든 OS/모든 인자 조합 검증과 외부 부품 자료 진위 보증은 완료 항목에 포함하지 않습니다.

## 2026-10-22 검증 범위

검증 회로 5종의 17개 측정 항목을 시스템 ngspice 44.2 배치, KiCad 번들 ngspice 45.2 공유 라이브러리, LTspice 24.0.12(Wine 배치), Qucs-S 26.1.1(시스템 ngspice 엔진, GUI·CLI dataset) 네 경로로 실행했고 네 경로 모두 17/17이 사양 허용 오차(이론값 대비 2%, `gain_db_10hz`는 0.17 dB) 안에 들었습니다. Qucs-S가 만든 넷리스트는 기준 넷리스트와 5종 모두 등가였고, LTspice 판정 5건은 독립 재검증에서 모두 확인됐습니다. ngspice 계열 세 경로는 서로 거의 같은 값을 냈지만(최대 상대 차이 0.001% 미만) LTspice는 `04-diode-rectifier` 순방향 강하에서 1.74% 차이가 나 경로 간 1% 기준은 아직 충족하지 못했습니다. KiCad 회로도에서 SPICE 넷리스트를 내보낸 경로는 `01-rc-step` 1종입니다. 설치·버전 정본은 [시뮬레이터 구성 계약](agents/20261022-172859_circuit-simulators-linux.md), 원본 증거는 `docs/검증/20261022-172859-circuit-simulators/`와 `projects/sim-validation-20261022/`입니다. 제조사 IC 모델, ngspice 45 이상이 필요한 Qucs-S 마이크로스트립 해석, 실측 대비 검증과 회로 정격 보증은 완료 항목에 포함하지 않습니다.

KiCad 편집기 내장 시뮬레이터 GUI 경로도 같은 날 ACUW 레인에서 5종 모두 실행해 17/17이 통과했고 캡처 재판독 5건이 confirmed였습니다(`projects/sim-validation-20261022/kicad-gui/`). GUI 값은 콘솔 `.meas` 텍스트와 CSV 재계산으로 확인했으며 화면 판독에 의존하지 않았습니다.
