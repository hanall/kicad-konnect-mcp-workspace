# 보안 및 라이선스

## 공급망

| 항목 | 통제 |
|---|---|
| upstream | 공식 GitLab/GitHub HTTPS origin만 허용 |
| version | release tag와 commit SHA를 함께 고정 |
| Rust crates | upstream `Cargo.lock`과 crates.io checksum 사용, `--locked` 강제 |
| Git dependency | `Cargo.lock`에 `git+` source가 있으면 검증 실패 |
| Python/npm | root Python은 표준 라이브러리만 사용, 새 패키지는 홈 guard와 감사 필수 |
| runtime state | `.runtime-home`에 격리, Git 제외 |
| 회로 시뮬레이터 | Qucs-S·LTspice는 버전·SHA256·게시일을 `config/qucs-s.lock.json`·`config/ltspice.lock.json`과 설치 스크립트 상수에 함께 고정, ngspice·Wine은 Debian 공식 패키지 버전을 `make sim-runtime-verify`로 대조 |

KiCad `10.0.6`과 Konnect `v0.13.0`은 tag object와 commit을 잠금 파일에 각각 고정합니다. Git tag/commit 고정, AppImage minisign, crates.io checksum, 취약점 감사는 서로 다른 검증입니다. 서명 없는 Git 자료를 서명 검증으로 표현하지 않습니다. KiCad 라이브러리의 파일·디렉터리·symlink 목록, mode와 파일 SHA는 AppImage에서 추출한 고정 manifest로 전수 검증합니다.
Qucs-S는 릴리스 서명을 제공하지 않아 AppImage SHA256을 GitHub API digest와 릴리스 `hashes.sha256` 두 출처로 교차 대조합니다. LTspice MSI는 Authenticode 서명을 검증하지 않았고 ADI 공식 HTTPS 호스트에서 받은 파일의 로컬 SHA256만 고정합니다. 두 경우 모두 서명 검증으로 표현하지 않습니다.

## MCP 실행

- 기본 transport는 `stdio`입니다.
- HTTP transport는 `127.0.0.1`만 허용합니다.
- MCP tool이 읽고 쓰는 프로젝트 경로는 `projects/`로 제한하는 추가 정책 계층을 로드맵에 둡니다.
- 과거 auto-install 및 현재 명시적 `init`은 실제 HOME이 아닌 `.runtime-home`에서만 수행합니다.
- 선택 STDIO 중계(`KONNECT_GUI_SYNC=1`, `KONNECT_SIM=1`)도 같은 실행기를 거쳐 Konnect를 자식으로 띄우며 upstream binary를 직접 실행하지 않습니다. 중계 프로세스 자체는 HOME 격리 전에 분기하므로 사용자 HOME에서 실행됩니다.
- 시뮬레이션 도구는 넷리스트를 실행합니다. ngspice는 배치 모드(`-b`)에서도 넷리스트 `.control` 블록의 `shell` 명령으로 OS 명령을 실행하고(2026-10-22 ngspice 44.2에서 무해한 `echo`로 확인), `.include`·`.lib`는 호스트 파일을 읽습니다. 제조사 모델·외부 넷리스트처럼 신뢰 경계 밖 입력은 내용을 확인한 뒤에만 실행합니다.

## 라이선스 경계

| 구성요소 | 라이선스 | 핵심 영향 |
|---|---|---|
| KiCad | 주로 `GPL-3.0-or-later` | 수정·배포 시 해당 source와 라이선스 의무 검토 |
| Konnect | `AGPL-3.0-only` | 파생 프로그램을 네트워크로 제공할 때도 source 제공 의무 가능 |
| root 통합 계층 | `AGPL-3.0-only` | Konnect 확장과 일관된 공개 개발 기본값 |
| ngspice (시스템 apt·KiCad 번들) | 주로 `BSD-3-Clause`, 일부 파일 `GPL-2+`·`LGPL-2` 등(Debian copyright 기준) | 호스트 실행 도구로만 사용, 저장소에 포함·재배포하지 않음 |
| Qucs-S | `GPL-2.0-or-later` | AppImage를 저장소에 넣거나 재배포하지 않음, 수정·배포 시 GPL 의무 검토 |
| LTspice | ADI 사용권(무료, 비공개 소스, 설치 시 동의) | 바이너리·부품 라이브러리를 저장소에 넣거나 재배포하지 않음, 사업용 사용·자동 배포 조건은 사용권 원문 별도 확인 |
| Wine | 주로 `LGPL-2.1-or-later` | Debian 공식 패키지를 수정 없이 사용 |
| 제조사 SPICE 모델 | 제조사별 사용 조건 | 저장소 커밋·재배포 전 모델별 조건 확인, Debian ngspice도 TI 모델을 DFSG 비호환으로 제외 |

단순 집합과 파생·결합 저작물의 판단은 구현 방식에 따라 달라질 수 있습니다. 비공개 사업용 서비스나 배포 제품은 Konnect의 commercial license 또는 별도 법률 검토를 거칩니다.
회로 시뮬레이터는 root 저장소와 결합하지 않는 별도 실행 프로그램입니다. 저장소에는 잠금 파일·설치 스크립트·넷리스트·로그·측정값과 검증 사양에 쓴 단순 모델만 둡니다. LTspice를 사업용 서비스나 배포 제품의 일부로 호출할 때도 ADI 사용권 원문을 별도로 검토합니다.

## 하드웨어 안전

ERC/DRC 통과는 전기적 안전이나 제조 가능성을 보증하지 않습니다. 전압·전류·열·절연·극성·부품 정격·EMC·규제 요구는 datasheet와 실측에 근거해 별도 검토합니다.
시뮬레이션 통과도 같은 경계입니다. 이론값·엔진 간 일치는 모델과 넷리스트 변환의 재현성 증거이며 제조사 모델의 정확성, 부품 정격, 열·실측 성능을 보증하지 않습니다.

## 2026-10-06 승인 예외와 잔여 리스크

- 사용자가 최신 upstream 업그레이드의 공급망 예외와 Freerouting `2.5.0`의 7일 미만 age 예외를 각각 승인했습니다. 정확한 JAR/JRE 출처와 해시는 `config/freerouting.lock.json`, KiCad는 설치 manifest에 기록합니다.
- Freerouting GitHub asset SHA는 전송 검증이며 독립 서명이 아닙니다. 실제 라우팅은 telemetry 두 경로 차단과 네트워크 namespace 격리에서 검증했습니다. 선택 런타임의 `-Duser.home`도 전용 HOME으로 고정합니다.
- JLCPCB DB 피드는 Bouni의 제3자 공개 배포입니다. bounded 다운로드, SQLite schema/quick_check, 수신 SHA, atomic replace를 검증해도 제조사 원문의 진위·재고·가격 최신성은 보장하지 않습니다.
- Specctra의 Git 의존성과 취약 전이 의존성을 제거하고 필요한 parser/writer를 출처·MIT 고지를 보존해 내부화했습니다. 정상 golden, malformed 입력과 회귀 시험은 유지합니다.
- audit 결과 0은 조회한 시점에 알려진 advisory 범위이며 미발견 취약점 0의 증명이 아닙니다.

## 2026-10-22 승인 예외와 잔여 리스크

- 사용자가 2026-10-22 그릴링에서 Qucs-S 26.1.1 AppImage의 `/opt/qucs-s/26.1.1` 고정 설치(1라운드 Q1), Wine 전체(`wine32:i386` 포함) apt 설치와 LTspice 24.0.12 MSI 직접 URL 설치(2라운드 Q3, 3라운드 Q10)를 각각 승인했습니다. LTspice는 공급망 지침의 직접 URL 설치 기본 금지에 대한 예외입니다. 승인 근거와 검토한 대안은 각 잠금 파일 `approval` 필드에 있고, 두 설치 파일 모두 7일 age gate를 통과했습니다(승인 시점 Qucs-S 179일, LTspice MSI 916일).
- LTspice `latest` URL은 같은 주소의 파일이 바뀔 수 있습니다. 설치 스크립트는 잠금 SHA256과 다르면 중단하므로 재설치 실패는 정상 거부입니다. 갱신은 새 SHA·버전·게시일을 잠금 파일과 스크립트 상수에 동시에 반영하는 별도 승인 작업이며 Qucs-S·LTspice는 자동 갱신하지 않습니다.
- 시스템 ngspice와 Wine은 Debian 패키지입니다. 이 호스트의 unattended-upgrades는 Debian 안정·보안 origin을 자동 설치하고 두 패키지에 hold나 blacklist가 없어 버전이 바뀔 수 있습니다. 바뀌면 `make sim-runtime-verify`가 버전 불일치로 실패하며, 회귀를 다시 확인한 뒤 잠금 파일과 스크립트 상수를 갱신합니다.
- Wine은 샌드박스가 아닙니다. LTspice prefix의 `z:` 드라이브는 `/`에 연결되어 비공개 바이너리가 사용자 권한으로 홈 전체를 읽을 수 있고, `/dev/ttyUSB0`·`/dev/ttyACM0` 같은 시리얼 장치도 COM 포트로 연결됩니다. 네트워크 namespace 격리와 업데이트 확인·telemetry 차단은 Freerouting과 달리 검증하지 않았습니다. `WINEDLLOVERRIDES`는 wine-mono·gecko 다운로드 대화상자만 막습니다.
- 이번 설치의 시스템 전역 변경은 Debian 패키지(`ngspice`, `wine`·`wine64`·`wine32:i386`·`libwine`)와 Qucs-S의 `/opt/qucs-s/26.1.1`·`/usr/local/bin/qucs-s`·desktop/icon 파일입니다. `i386` multiarch는 그 전부터 켜져 있었습니다. LTspice 자체는 사용자 홈의 Wine prefix와 `~/.local/bin/ltspice`에만 있습니다.
- 시뮬레이션 MCP 도구의 입력 경계는 2026-10-22 중계 v1에서 다음과 같이 닫았습니다. 입력 넷리스트의 `.control`~`.endc` 블록은 옵션과 무관하게 항상 제거하고, `directives`는 `.model`·`.include`·`.param`·`.option`·해석·측정 지시어 화이트리스트와 제어 명령 토큰(`shell`, `source`, `write`, `set` 등) 거부로 검사하며, 회로도·넷리스트 읽기는 저장소·사용자 홈·시스템 라이브러리 루트, 작업 디렉터리·출력 쓰기는 저장소 안(또는 `KONNECT_SIM_ALLOWED_ROOTS`)으로 제한하고, `.include`·`.lib` 대상은 허용 루트와 `.control` 부재를 확인합니다. 거부 입력 회귀(`shell touch` 넷리스트·지시어·`analysis.args` 3경로, 허용 루트 밖 `work_dir`·`output`)는 `make test-sim-mcp`에 있습니다. ngspice 자체는 샌드박스가 아니므로 신뢰 경계 밖 모델 파일은 여전히 내용을 확인한 뒤에만 포함합니다.
- 설치 SHA·매니페스트 대조는 받은 파일이 고정값과 같다는 전송·무결성 검증입니다. 독립 서명이나 악성코드 부재를 증명하지 않습니다.
