# 아키텍처

## 목표

자연어 작업을 MCP tool call로 변환하되, 설계 데이터의 정본은 KiCad 파일과 실제 KiCad 10 엔진에 둡니다.

```text
AI / MCP client
      |
      | initialize, tools/list, tools/call
      v
scripts/run-konnect.sh
      |
      +-- KONNECT_GUI_SYNC=1 -- konnect-mcp-gui.py --> synchronize_schematic_edit 추가
      |
      +-- KONNECT_SIM=1 ------- konnect-mcp-sim.py --> 시뮬레이션 도구 4종 추가 --> ngspice / LTspice 배치
      |
      | 중계는 자기 플래그만 0으로 바꿔 run-konnect.sh를 자식으로 다시 실행하고 나머지 요청을 전달
      | 마지막 run-konnect.sh가 HOME/XDG를 .runtime-home으로 격리한 뒤 Konnect binary를 exec
      v
Konnect MCP router
      |
      +-- schematic S-expression engine -- atomic write --> *.kicad_sch
      |
      +-- KiCad 10 IPC API ------------ NNG/protobuf --> PCB Editor
      |
      +-- kicad-cli -------------------- process ------> ERC/DRC/export, SPICE netlist
      |
      +-- observability ---------------- JSONL --------> .runtime-home
```

## 데이터 경계

| 경계 | 정본 | 실패 시 원칙 |
|---|---|---|
| 회로도 편집 | `.kicad_sch` | 임시 파일, fsync, rename을 통한 atomic write 유지 |
| PCB 실시간 편집 | 실행 중인 KiCad 10 PCB Editor | IPC 실패를 파일 직접 변경으로 조용히 대체하지 않음 |
| ERC/DRC | KiCad 10 `kicad-cli` 결과 | exit code와 report를 함께 보존 |
| 제조 산출물 | 검증된 PCB commit에서 생성한 Gerber/drill/BOM/position | 입력 commit과 생성 명령을 manifest에 기록 |
| 회로 시뮬레이션 | `.kicad_sch`의 `Sim.*` 필드·시뮬레이션 지시와 검증 사양(`spec.json`)의 이론값·허용 오차 | 엔진 이름·버전·넷리스트·원본 로그를 측정값과 함께 보존, 한 엔진의 실패나 누락 측정을 다른 엔진 결과로 조용히 대체하지 않음 |
| MCP 계약 | tool/schema/config/CLI | 호환성 또는 명시적 migration 필요 |

root 저장소와 Konnect fork 모두 GitHub Actions를 사용하지 않습니다. 검증 정본은
개발 호스트에서 실행한 `make check-local` 결과이며, root gitlink는 검증된 Konnect
fork commit만 가리킵니다.

## 안전한 기본 실행

구 Konnect v0.2.2는 첫 MCP 실행 때 사용자 설정을 자동 수정했습니다. 0.13.0 계열은 명시적 `init`을 사용하지만 같은 격리 경계를 유지합니다. 이 프로젝트의 `.mcp.json`은 binary를 직접 실행하지 않고 `scripts/run-konnect.sh`를 호출합니다. wrapper는 HOME과 XDG state를 `.runtime-home`으로 격리해 실제 사용자 설정을 보존합니다.
프로젝트 MCP 등록(`.mcp.json`, `.codex/config.toml`)은 `KONNECT_GUI_SYNC=1`과 `KONNECT_SIM=1`을 켭니다. `run-konnect.sh`는 HOME 격리 전에 해당 STDIO 중계로 분기하고, 중계는 자기 플래그만 0으로 바꿔 같은 실행기를 자식으로 다시 띄웁니다. 따라서 연결은 GUI 중계 → 시뮬레이션 중계 → Konnect 순서로 이어지고 `.runtime-home` 격리는 마지막 Konnect 프로세스에만 적용됩니다. 중계 자신은 사용자 HOME에서 실행되므로 ACUW 레인과 `~/.local/bin/ltspice`를 호출할 수 있습니다. upstream binary와 core 도구 수는 바뀌지 않으며, 현재 연결에 어떤 중계가 붙었는지는 `get_installation_info`의 `gui_sync_extension`·`simulation_extension` 필드로 확인합니다. 시뮬레이션 중계의 실행 제한 100초는 바깥 GUI 중계의 응답 제한 120초 안에 끝나도록 정한 값입니다.

## 검증 계층

```text
source provenance
      |
      v
root contract test
      |
      v
Konnect format + unit + doc + clippy
      |
      v
MCP initialize + tools/list smoke
      |
      v
KiCad 10 CLI ERC/DRC/export
      |
      v
KiCad 10 GUI/IPC acceptance
```
회로 시뮬레이션 검증은 위 체인과 나란한 별도 축입니다. `make check-local`의 root unittest(`tests/test_*.py` 전체)는 시뮬레이터 사양·잠금 계약을 항상 검사하고, 엔진과 Konnect binary가 있는 호스트에서는 설치 `--verify-only`, 시스템 ngspice 회귀, 시뮬레이션 중계 계약까지 실행합니다(없으면 skip). `make sim-runtime-verify`·`make sim-verify`·`make test-sim-mcp`, KiCad 번들 엔진 회귀(`scripts/sim-validation-run.py --engine kicad-bundled`)와 ACUW 레인의 LTspice·Qucs-S 교차 실행은 별도로 실행하고 증거를 남깁니다. 어느 단계의 통과도 해당 엔진 경로의 재현성 증거이며 회로 정격 합격이 아닙니다.

## 개선판 추가 경계

- 뷰어: S-expression 원본은 읽기 전용, 임시 snapshot에서 실제 `kicad-cli` SVG를 생성합니다. 임의 외부 bind 대신 `127.0.0.1`과 난수 capability 경로를 사용합니다. 페이지·상태·SVG·브라우저 로딩 ACK를 함께 확인해야 ready입니다.
- whole-footprint IPC: 같은 document의 메모리 snapshot과 KIID를 대조해 protobuf가 보존하지 못하는 point·group·units 등은 쓰기 전에 거부합니다. 닫힌 PCB의 별도 opt-in은 원문 보존·revision·CAS·readback을 거칩니다.
- raw 오류와 적용 결과: 호출 성공, 실제 적용, 원복, 미확정 상태를 구분합니다. rollback 도중 외부 writer가 바꾼 파일을 이전 snapshot으로 덮지 않습니다.
- 런타임 HOME: 기본 `.runtime-home` 외 격리는 `KONNECT_RUNTIME_HOME`의 `.artifacts` 하위 canonical 디렉터리만 허용합니다. 심볼릭 링크 탈출은 거부합니다.
- 공개 기능 시험: catalogue(형식/거부), headless(회로/라이브러리), PCB(GUI/IPC), service(제조/네트워크/라우터)의 ledger를 같은 바이너리 SHA에 결속해 병합합니다.

## 회로 시뮬레이션 경계

2026-10-22 사용자 승인으로 네 엔진 경로를 고정했습니다. 버전·설치 경로·명령·알려진 제약의 정본은 [시뮬레이터 구성 계약](agents/20261022-172859_circuit-simulators-linux.md)과 `config/qucs-s.lock.json`·`config/ltspice.lock.json`이며, 이 절은 데이터 흐름과 경계만 다룹니다. AI 작업 절차는 프로젝트 스킬 [`skills/kicad-simulation/`](../skills/kicad-simulation/SKILL.md)을 따릅니다.

```text
*.kicad_sch (Sim.Device / Sim.Type / Sim.Params / Sim.Pins / Sim.Library / Sim.Name)
      |
      | set_simulation_model -> upstream edit_schematic_component (MCP 쓰기)
      | export_spice_netlist, generate_netlist(format=spice) -> kicad-cli sch export netlist
      v
SPICE netlist (.cir) + 분석·.meas 지시 (run_spice_simulation이 조립)
      |
      +-- 시스템 ngspice (apt) ----------- batch -------> .meas 로그
      +-- KiCad 번들 libngspice ---------- ctypes ------> .meas 로그
      +-- LTspice (Wine) ----------------- -b batch ----> .log / .raw  [ACUW 레인]
      +-- Qucs-S -> 시스템 ngspice -------- GUI / CLI ---> dataset      [MCP 실행 대상 아님]
      |
      v
이론값·허용 오차 판정 --> .artifacts/sim-runs/ 또는 projects/<검증>/ + docs/검증/
```

- 엔진 정본: KiCad 회로도 편집기의 시뮬레이터는 AppImage 번들 ngspice를, Qucs-S는 시스템 ngspice를 씁니다. 두 버전이 다르므로 측정값에는 엔진 이름과 버전을 함께 남기고, 편집기와 같은 엔진 결과가 필요하면 `kicad-bundled-ngspice`를 지정합니다.
- 회로도 쓰기: `Sim.*` 필드와 시뮬레이션 지시도 회로 데이터입니다. MCP에서는 `set_simulation_model`이 upstream `edit_schematic_component`만 호출하고, 그 밖에는 승인된 공유 화면 GUI로만 고칩니다. `.kicad_sch`를 직접 텍스트 편집하지 않습니다. 엔진 계층(`scripts/sim_engines.py`)은 `.kicad_*`를 직접 읽거나 쓰지 않고 `kicad-cli` 내보내기 결과인 넷리스트·로그·dataset만 다룹니다.
- 실행 경계: 시스템·번들 ngspice는 헤드리스로 실행합니다. LTspice는 Wine GUI 프로세스라 `lane` 인자로 지정한 이 프로젝트 전용 ACUW 레인에서만 배치 실행하고, Qucs-S는 MCP 실행 엔진이 아니라 레인 GUI 병행 확인용입니다. 레인 open과 `run-in-workspace.sh` 모두 `ACUW_LANE_MEMORY_MAX=16G`를 붙입니다.
- MCP 계약: 도구 4종(`list_simulation_engines`, `export_spice_netlist`, `set_simulation_model`, `run_spice_simulation`)의 이름·schema는 공개 계약입니다. 바꿀 때는 호환성·migration·회귀(`make test-sim-mcp`)를 함께 갱신합니다. 결과는 `isError=false`여도 `all_pass`·`errors`·`missing_measurements`를 확인합니다.
- 판정 경계: 이론값 일치와 엔진 간 일치는 모델과 넷리스트 변환의 재현성 증거입니다. 제조사 모델의 정확성, 부품 정격, 열·실측 성능을 보증하지 않습니다.
